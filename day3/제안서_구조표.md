# 내 제안서 구조표

기존 템플릿(제안서_템플릿.html)을 참고하지 않고 처음부터 짰다. 기준은 하나 —
"이 절을 채울 데이터 함수 이름을 지금 댈 수 있는가." 최대 7개, 사람이 쓰는 절은 둘뿐이다.

| 절 제목(질문형) | 이 절이 답하는 질문 | 채우는 데이터 함수 | 자동/사람 |
|---|---|---|---|
| 한 장 요약 | 전체를 압축하면 무엇인가 | 나머지 절을 압축(이 파일이 조립) | 자동 |
| 1. 지금 어디서 새고 있습니까 | 어느 단계에서 가장 많이 빠지는가 | `core.metrics.funnel()` | 자동 |
| 2. 어느 지점에서 벌어집니까 | 어느 축(담당자/채널)에서 격차가 나는가 | `core.metrics.topic_evidence()` → `funnel_by()` | 자동 |
| 3. 얼마짜리 문제입니까 | 이 격차를 방치하면 연간 얼마나 손해인가 | `core.metrics.proposal_topics()`의 규모_연간건수 | 자동 |
| 4. 무엇을 하자는 것입니까 | 무엇을 하고, 하지 말고, 다시 잴 것인가 | `day2/제안카드.md` (카드를 그대로 옮김) | 자동 |
| 5. 이 판단이 틀릴 수 있는 지점 | 이 제안이 틀린다면 무엇 때문인가, 철회 조건은 무엇인가 | — | **사람** |
| 6. 무엇을 결정해 주셔야 합니까 | 승인/조건부 승인/보류 중 무엇을 요청하는가 | 선택지 셋은 자동, 요청 문장은 사람 | **사람**(후보 자동) |

## 만들지 않은 절

| 후보 절 | 왜 안 만들었나 |
|---|---|
| 실험 결과 | 이 데이터엔 무작위 배정 실험 테이블 자체가 없다 — 채울 함수가 없다 |
| 경쟁사 비교 | 비교할 외부 데이터가 없다 |

"이 도메인에는 없음"이 있다는 것 자체가, 다 만들 수 있다고 착각하지 않았다는 증거다.

## 왜 이 순서인가

리더가 결재를 내리기까지 머릿속을 지나가는 질문 순서를 그대로 절 순서로 삼았다 —
무슨 일이 일어나는지(1) → 어디서 벌어지는지(2) → 얼마짜리인지(3) → 그래서 뭘 하자는
건지(4) → 틀리면 어떻게 되는지(5) → 나한테 뭘 해달라는 건지(6). 순서를 바꾸면
설득이 안 된다 — 규모(3)를 제안(4) 뒤에 두면 "왜 해야 하지"가 안 풀린 채로 제안을
읽고, 위험(5)을 요청(6) 뒤에 두면 결정한 다음에 리스크를 듣게 된다.
